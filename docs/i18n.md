# i18n and RTL / LTR

The site uses `i18next` and `react-i18next`.

## Files

Translation JSON files live under:

- `src/assets/locales/ar/`
- `src/assets/locales/en/`

Namespaces:

- `common`
- `home`
- `about`
- `deanMessage`
- `departments`
- `programs`
- `news`
- `announcements`
- `faculty`
- `services`
- `events`
- `contact`

They are registered in `src/i18n.js`.

## How language is chosen

Default language is Arabic (`ar`).

1. `index.html` reads `localStorage.lang` before React loads and sets `lang` / `dir` on `<html>` so the first paint matches the saved choice.
2. `src/i18n.js` uses the same `localStorage` value as the i18next `lng`.
3. `App.jsx` syncs language and document direction again on mount.

## Language switcher

The header button switches between Arabic and English. On change it:

1. Calls `i18n.changeLanguage(lang)`
2. Sets `document.documentElement.lang`
3. Sets `document.documentElement.dir` to `rtl` for Arabic and `ltr` for English
4. Saves the choice in `localStorage` under `lang`

## Usage in components

```jsx
const { t } = useTranslation('faculty');
t('page.title');
```

For keys in another namespace:

```jsx
t('departmentsList.cyberSecurity.name', { ns: 'departments' });
```

UI text should come from translation keys so both languages stay in sync. Shared loading, error, and retry strings live in the `common` namespace.
